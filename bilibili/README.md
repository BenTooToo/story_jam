# Story Jam · B 站（Toy）网页版

## 导出

```bash
bash bilibili/export_web.sh
```

会生成 `~/Desktop/程序programs/小游戏/story_jam/导出/B站版/` 下的 `story_jam_web/` 和 `story_jam_web.zip`
（约 77MB，上传 Toy 用这个 zip）。放在那里是照《Bilibili Toy 使用手册》第六节的约定。
每次上传都要升版本号（一次上传只升一次）：先改 `bilibili/VERSION`，导出时间（北京时间）由脚本自动加在后面，
显示在加载画面和选线界面的左上角。上传图标用 `bilibili/toy_icon_500.png`（500×500），4:3 的封面还没有。

本地试玩：在 `story_jam_web/` 里 `python3 -m http.server`，打开 `http://localhost:8000/index.html`。

## 网页版多了什么

- **触屏按键**（`Stories/Shared/Touch/touch_pad.gd`，自动加载 `TouchPad`）：只在触屏设备上出现。
  按下去等于按对应的键盘键，所以各关读键盘的代码没改。
  - 底座是电梯数字面板（`Assets/Edited/数字面板.png`），方向键用跳舞关的绿 / 红箭头（P1 绿、P2 红），按下亮一圈暖黄。
  - 扔东西 / 打怪兽：单人左下 ← →、右下 ↑ 扔；双人每人一排四个。
  - 跳舞：单人拆成左右两半（← ↓ | ↑ →）；双人每人四个键正对自己的四条轨道。
  - 天台对决：左边十字键，右边 B / A。弹幕：左下摇杆（八方向），右下「慢」。QTE：整屏随便点。
  - 规则页的按键说明在手机上换成屏幕按键的写法，要按的就是屏幕按键；出规则时按键先收起来，进关再摆出来。
  - 点屏幕 = 点鼠标由 TouchPad 转发（项目里关掉了 Godot 自带的「触摸当鼠标」），这样按屏幕按键不会顺带点掉对话。
  - 想换成专门画的按键：把底座图和箭头换掉就行（`PANEL`、`ARROW_P1`、`ARROW_P2`），九宫格边距是 `PANEL_MARGIN`。
- **Toy SDK**（`Stories/Shared/Web/toy.gd`，自动加载 `Toy`）：经 `shell.html` 的 `window.gameToy` 调用，Godot 每帧去取结果。
  作者 UID 和介绍视频 BV 号是这里的 `AUTHOR_MID`、`VIDEO_BVID`。**介绍视频发了以后把 BV 号填进 `VIDEO_BVID`**，「介绍视频」按钮才会出现。
- **存档 + 云存档**（`Stories/Shared/Web/save_data.gd`，自动加载 `SaveData`）：记达成的结局（3 个）、画质设置、开局关注卡片弹过没有。
  本地 `user://save.json`，网页版把结局同步一份到 Toy 云存储（键名 `story_jam_save`）。启动时读回来合并（结局取并集），
  合并完之前不往云端写；没登录 / 读失败就整局不碰云端，也不挡开局。只在打出结局时写。
- 没有排行榜（2026-10-14 定：这个游戏用不上）。
- **关注入口**（不锁任何内容：Toy 规定不能拿关注 / 点赞 / 三连锁基础功能，违反会下架）：
  - 四位作者：本2兔、罗马特、小名是木木、小高星。有主页的三位名字能点，去各自的 B 站主页；罗马特不发视频，
    只写名字（名单在 `toy.gd` 的 `AUTHORS`，UID 留空就是不能点）。
  - 第一次进游戏弹一次「喜欢的话，可以关注一下我们」，点别处就跳过，之后不再弹（`thanks_card.gd` 的 `show_follow_prompt`）。
  - 选线界面底下一行；通关后的「感谢游玩」卡片上先突出这条线的作者（`ROUTE_AUTHORS`），再列全部。
  - 感谢语跟着关注 / 三连状态变。SDK 只查得到玩家有没有关注上传 Toy 的号（小名是木木），别人的查不到。
  - 在 B 站 App 里用 `toy.navigate`，其他地方新开标签页。
- **画质**：选线界面右上角「画质：标准 / 流畅」，手机默认流畅。流畅时网页只按游戏 2 倍分辨率（1280×720）渲染，一次性粒子只放 40%。
- **手机稳定性**：帧率封顶 60；超过 10 秒的声音一律流式播放（`Toy._stream_if_long`，网页版默认会把整首歌解码进内存不释放，
  几首歌就能把 App 撑到闪退）；程序生成的提示音按参数缓存，不再每下现做一个。
- **不沉浸、不强制横屏**：App 底下那条点赞、评论栏要留着。竖屏时提示一次「建议横屏」，点一下就收起。
- **加载**：wasm 编译失败（手机内存不够、流断了）会整块重下再编译一次，还不行就在加载界面报错；下完 12 秒还没启动写
  「手机有点慢，正在启动……」，60 秒报「启动超时」（照手册附录 N，`bilibili/shell.html`）。
- **音频缓冲**：网页上 `audio/driver/output_latency.web = 120`（毫秒），主线程卡一下背景音乐不会断。
  手册里《寻找伪人》用的是 200；这里是音游，打击音效会跟着晚，所以折中取 120。
  跳舞关的谱面时间按播放位置减掉输出延迟算，缓冲大小不影响判定。帧率也不锁 30（音游判定按帧走）。

## 体积

pck 约 59MB，几乎全是曲子（mp3 约 26MB）和隐藏关的三段背景视频（ogv 25MB），这些本来就压过，所以 pck 不再 gzip。
引擎 wasm 39.5MB，gzip 后 10MB（`index.wasm.gz.bin`）。
`可爱的小曲.wav` 源文件 24MB，但导入设置是 QOA 压缩，进包只有 3.4MB，不用转格式。

还想更小的话：三段 ogv 用更低码率重新编码（本机的 ffmpeg 没有 libtheora，要先装一个带 theora 的）。
